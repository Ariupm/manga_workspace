# 剧情驱动动作模板与骨骼图生成方案

状态：待实施的设计方案，不代表功能已实现。

## 1. 目标与原则

目标：从当前剧情中确定人物正在做什么、处于哪个动作阶段、与谁或什么发生关系，生成可解释、可编辑、可复现的动作模板骨骼图，供现有 SD/ControlNet 链路使用。

默认优先级：剧情动作与关键关系成立 → 人物身份和连续状态正确 → 人体结构合理 → 构图自然。默认不强制露腿或藏腿；用户明确指定景别或构图时尊重其选择，若与关键动作表达冲突则报告冲突。

骨骼不能独自保证人物身份、服装、手指、眼球视线或道具外观。它负责身体几何，其他约束继续由对应参考资产、控制单元、局部阶段和审核负责。

“通用”指可组合的动作机制与明确的能力边界，不承诺有限模板覆盖所有剧情。未覆盖动作不得静默套用站姿后标为成功。

## 2. 当前基础与改造范围

沿用 lib/pose-v2.ts 的动作识别、步态、双人交互、共享接触关系和参数编辑能力，以及现有 OpenPose 18 点输出兼容性。新增 v3 规划器，不直接破坏历史 v2 recipe。

当前近景/中景统一进入 upper_body，将 8—13 号髋膝踝移出画布。v3 默认改为 auto_story：先生成完整动作，再选择能表达剧情的构图，最后统一投影。禁止用修改关节坐标到固定画外 y 值代替完整动作数据。

不要简单恢复所有腿部线条，也不要把完整骨架一律缩小塞进画面。两者都会造成新的构图偏置。

## 3. 完整数据流

剧情与人工选择 → 动作语义计划 → 模板组合与阶段选择 → 完整人体/对象/支持面几何 → 关键可见证据 → 构图候选评分 → 统一投影与可见性 → OpenPose/对象/支持面控制图 → 请求覆盖校验 → 基础生成与局部阶段 → 剧情语义审核 → 正式候选。

每个阶段保存版本、输入来源、参数、决策原因和哈希。相同输入、模板版本与变体 seed 应产生相同控制图。

## 4. 动作语义计划

每个人物记录：characterId、basePosture、primaryAction、secondaryActions、phase、facing、activeHand、supportHand、supportLeg、targetId、gazeTarget、emotionIntent、actionEvidence、source、confidence。

每个关系记录：relationId、actor/receiver、objectInstanceId、对象持有者、动作前后状态、接触点、方向与遮挡顺序。镜头只选择一个明确瞬间，不能把“起身、拿手机、走出门”同时混成一个骨架。

输入优先级：当前人工明确选择 > 当前确认的视觉规格 > 当前剧情结构化分析 > 兼容文本推导。字段冲突保留来源并仲裁；不启用未确认旧视觉规格，不使用人物名或具体任务 ID 硬编码。

识别分为两步：AI 提取语义；确定性模板选择与几何求解。AI 可以选择已注册模板与参数，不直接随意编造整套坐标作为默认执行结果。

## 5. 模板体系与首版覆盖清单

模板由基础姿态、动作组件和关系组件组成，避免为每一种物品复制骨架。

| 层 | 首版模板/组件 | 必需参数或动作证据 |
|---|---|---|
| 基础姿态 | 站、坐、蹲、单膝跪、双膝跪、斜靠、平躺、侧躺 | 躯干/骨盆方向、支撑点、身体高度 |
| 移动 | 走、快走、跑、跨步、停止 | 支撑腿、摆动腿、步幅、摆臂、行进方向 |
| 姿态变化 | 起身、坐下、弯腰、转身、起蹲 | 起始/接触/完成阶段、重心代理与支持面 |
| 单人上肢 | 指向、伸手、抬手、触脸、遮挡、招手 | 肩肘腕方向、目标、左右手 |
| 持物 | 单手持物、双手持物、搬抱、提拎 | 物体尺寸、握持类型、接触带、负重姿态 |
| 使用物品 | 阅读、书写、按压、旋转、饮用、推拉 | 工作点、主动手/辅助手、对象用途 |
| 放取 | 从高/中/低处拿取或放置 | 对象高度、身体屈曲、接触阶段 |
| 双人 | 交谈、递接、共同查看、握手、击掌、拥抱、搀扶、拉引、同行、对峙 | 双方角色、距离、共享对象、接触点、遮挡 |

现有合并类别必须拆成几何确实不同的子模板：走/跑、蹲/跪、握手/击掌、拥抱/搀扶、阅读/书写、推/拉。只改名称而不改关节拓扑不算完成。

各模板提供受约束的参数范围、适用条件、排斥条件、允许叠加组件、默认动作阶段和失败原因。例如持物手不能再承担开门动作；行走时持物手不自动摆臂；双手搬箱不能同时按门铃。

每个模板至少包含一个标准变体；左右镜像、动作阶段和力度由参数生成。镜像必须同步交换解剖左右、接触点和目标方向，不能只翻转图片。

## 6. 完整骨架与几何约束

保留完整动作空间骨架，再生成镜头空间骨架。第一版采用参数化 2D/2.5D 几何和前后层级，不将其宣传为完整 3D 物理模拟。

骨长采用角色比例参数，保持左右肢段基本一致；肩肘腕、髋膝踝用有约束的关节求解。脚部支撑、座面与骨盆、手与对象共享锚点。关节目标不可达时调整构图、角色距离或动作变体，不能无限拉长手臂。

坐姿关联座面高度；跪姿区分膝部支撑与脚部位置；走跑区分支撑/摆动腿及躯干倾斜。手部接触采用对象局部坐标，投影时与对象一起变换。

可见性区分 visible、occluded、out_of_frame、unknown。骨架保留被遮挡关节，实际控制图按渲染策略输出；明显不应出现在前景的遮挡肢体不能随意连线。2D 推导无法可靠确定透视或遮挡时提示人工调整。

## 7. 以动作可读性选择构图

新增 compositionPolicy：auto_story（默认）、preferred（景别偏好）、locked（用户明确锁定）。历史 camera 字段不能自动等同于人工 locked。

从完整动作生成有限构图候选：头肩、胸前动作、腰部以上、膝部以上、全身、含环境的全身。候选使用统一平移/缩放/镜头方向参数，不单独挪动下肢伪造裁切。

每个动作声明必须能被读出的证据，证据可以有替代方案：

- 看手机：头部、手机、持握关系和朝向；腿不是必需项。
- 走出门：人物与门口的空间关系、移动证据；若强调跨门槛，脚与门槛接触必须可见。
- 坐沙发：坐姿身体结构与沙发支持关系；是否显示脚不固定。
- 蹲下捡物：降低的身体姿态、手/物体/地面关系；不能只剩无法辨别动作的正脸。
- 递物：双方主动手、共享对象及交接阶段；腿是否出现不决定合格。

候选先满足硬条件：必需证据可见、关键接触不被裁断、人物不越出声明区域、明确人工约束成立。再评分比较动作可读性、脸与道具像素尺寸、遮挡、环境信息、画面留白和风格一致性。权重可配置并保存，不假定第一版评分已等价于视觉效果评价。

全部候选不满足时返回 needs_pose_edit/needs_story_clarification。不能通过删除关键证据让校验通过。auto_story 不产生“露腿即失败”的检查；locked 才按用户要求检查裁切。

## 8. 每个镜头与模板的交付物

每个模板包含 manifest.json、参数 schema、标准完整骨架 JSON、基础 SVG/PNG、变体目录、适用说明和程序验收案例。

每个镜头输出 PoseScenePlanV3、完整骨架、实际投影骨架、可见性清单、动作证据清单和控制文件：

1. full-pose-preview.svg/png：完整动作与编号，可附对象/支持面标注，仅供人审。
2. control-openpose.png：黑底、后端兼容的骨骼颜色与连线、匹配请求宽高，不带文字/坐标/家具线。
3. control-prop.png 与 control-support.png：按需要输出，独立使用合适控制单元，不能混入 OpenPose 图。
4. composition-preview.png：显示最终画框、动作证据和裁切范围，仅供人审。
5. recipe-fragment.json：模板版本、阶段、参数、变换、角色/对象/关系 ID、实际控制配置与覆盖状态。

18 点身体骨骼不等于完整手指/眼球控制。手指、面部关键点仅在后端模型兼容且数据可靠时独立接入；不通过添加任意点宣称已解决手指或视线问题。

## 9. 与当前出图链的衔接

只有一个最终 ProjectionPlan。prompt、人物 region、身份 mask、道具边缘图、支持面图、局部重绘 mask、UI 和审核均消费同一投影，不允许各自重新猜坐标。

默认移除由中景自动附加的“禁止腿/脚/全身”等硬负向词；按最终投影描述实际构图，强调剧情动作。locked 模式保留明确裁切约束。不能同时要求自动构图和强制禁止露腿。

身份和服装不由骨架模板定义。模板只关联 characterId，参考图选择和人物不变量仍从角色资产获取。表情是本镜头要求，不能被身份精修固定为微笑或正视观众。

CPU/GPU 都先检查必需控制覆盖：基础可并行的控制进入请求，延期部分必须有真实串行 executor。每阶段记录 planned/request_succeeded/semantic_pending/failed 等真实状态；HTTP 成功不等于动作完成。

局部阶段的允许区域与保留约束明确：身份只修头脸；道具/手部保留接触和姿态；视线保留身份与头部方向。最后一轮修改过的区域仍需审核。全局动作/身体结构失败回到基础构图阶段，不能靠脸部小 mask 补救。

任何变更影响模板、投影或关系几何时，使旧审批失效；候选保存源草稿、模板和投影哈希、阶段输出与最终审批。旧任务不可无提示混用 v3 mask 和 v2 坐标。

## 10. 界面设计

默认显示“按剧情自动构图”，同时显示剧情瞬间、动作模板及选择理由。提供完整动作、实际控制图、最终构图三个切换视图。

普通编辑项：动作阶段、朝向、主动手、步幅/力度、目标位置、支持面高度、双方距离和构图偏好。高级模式开放关节点编辑；编辑后重新校验接触与可达性并生成新版本。

不要求用户决定髋膝踝编号。警告应描述问题，例如“右手同时被分配给门把手和手机”“当前构图看不到跨越门槛的脚”，并提供可操作调整。

模板图库按动作分组展示骨架缩略图，每张标明适用动作与可调参数；未知动作可选择近似模板后编辑，明确标为人工调整，不标为自动精确匹配。

## 11. 兼容与实施步骤

阶段 A：建立 v3 schema、模板注册表、关节命名及动作证据契约；把现有模板映射到注册表，标出真实缺项。保留 v2 输出作为兼容。

阶段 B：实现完整骨架和关系几何；拆分合并动作模板，先完成站坐蹲跪、走跑、持物、取放和双人递接。输出可检查的模板图集。

阶段 C：实现 auto_story 候选构图与统一投影；加入膝上等部分身体模式、遮挡/画外状态；取消默认强制藏腿。

阶段 D：接入 prompt、recipe、worker 控制图/各 pass 和审批；新任务采用 v3，旧 recipe 固定走 v2 或经显式升级重建。

阶段 E：完成模板图库、关节编辑、审计与验收矩阵；扩展完整首版模板清单。三人以上、强透视、复杂地面翻滚等暂不自动宣称支持，提供编辑或上传入口。

主要文件：lib/pose-v2.ts 保留兼容；新增 lib/pose-v3/ 下的 schema、templates、planner、geometry、projection、validation、render 模块；修改 lib/prompts.ts、lib/types.ts、lib/semantic-review.ts、app/api/studio/route.ts、scripts/sd-worker.mjs 与 app/page.tsx。实现前按稳定 ISSUE ID 拆分登记，每项执行全链路冲突复核。

同步更新 PROJECT_DECISIONS.md 中“中景统一隐藏下肢”等旧规则：auto_story 服从动作证据与投影；locked 才服从强制裁切。不得保留相互矛盾的长期决策。

## 12. 程序验收与完成标准

矩阵覆盖：单人/双人/无人物；左右镜像；近中全景与自动构图；站坐蹲跪躺、走跑；不同阶段；单/双手与多关系；手机/书/杯/箱/工具等尺寸与形状；椅/沙发/床/地面；左中右区域；CPU/GPU；人工覆盖与旧任务兼容。

必须检查：

- 全身动作存在完整下肢，部分裁切保留原始数据，不使用固定画外坐标破坏动作。
- 相同模板不同关键参数产生符合动作机制的几何变化；不同模板不是相同骨架换名字。
- 关键动作证据在投影中可见，接触锚点与对象/支持面一致，骨长与关节范围合理。
- prompt、所有控制图、mask、recipe、UI 和审核的构图事实一致；非目标人物和非目标区域未被改写。
- 未覆盖动作、不可达接触、多手冲突和预算不足都有明确出口；失败/未应用不能标为完成。
- 修改后审批失效；全部 required verdict 通过后才允许正式候选回写。
- 同输入可重现同一骨架，SVG/PNG 尺寸、通道、背景、关节配色和连线符合目标 ControlNet 格式；预览标注不进入实际控制图。

完成交付：首版模板注册表和骨骼图集、逐镜头生成器、自动构图与编辑入口、全链路请求接入、覆盖矩阵报告及迁移说明。仅交付一批静态 PNG 不算完成。

验收遵循项目规则：不启动 SD，不生成测试漫画图；可以程序渲染骨骼/结构控制图并检查坐标和布局。程序逻辑验收通过不等于视觉服从率已证实，模型随机性与实际成图效果继续作为产品运行风险。
