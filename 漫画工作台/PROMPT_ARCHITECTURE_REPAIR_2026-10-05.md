# 提示词统一修复实施与验收

目标：让剧情和人工选择确定的画面事实贯穿生成链，降低重复、否定歧义、人物串扰和局部修复覆盖风险。提示词更短只是结果之一，不能代替身份、服装、动作和构图的一致性。

## 最终组织结构

```text
剧情 / 人工选择 / 已确认视觉规格 / 本人资产
  ↓ 既有优先级解析，有效人物事实与交互契约
共享编译器 scripts/prompt-compiler.mjs
  ├─ 公共正向：景别与镜头 → 具体场景 → 人数 → 构图 → 共同事件 → 光照 → 风格
  ├─ 人物正向（每人独立）：位置 → 身份 → 服装 → 动作 → 手与道具 → 表情 → 视线 → 当前状态与遮挡
  ├─ 全图负向：全图缺陷、公共限制、所有人物共有的排除项
  ├─ 人物负向：仅该人物的排除项
  └─ 阶段编译：从同一事实快照选择当前 pass 所需字段
  ↓ 正向事实编译、可识别否定分流、去重、冲突校验和来源审计
recipe.generationSpec.promptPlan（comic-facts-1）
  ↓ Regional 人物分区 / Pose 与 ControlNet / 原有 mask 和执行投影
基础请求 → 身份 / 服装 / 道具 / 手部 / 视线 / 交接局部请求
  ↓ 每个真实图像请求统一经过 prepareGenerationPromptRequest
实际请求审计 → 像素解码 / 后处理 / 配置的自动质量门
  ↓ 草稿一次整体确认 → 成品自动加入候选
```

BREAK 只分隔公共块与每个人物块；不会跨人物去重。普通预览与 Regional 使用同一组事实和编译结果，Canonical 负责保留块边界、校验并合并有效编辑，不再独立追加大量画面套话。

## 每层职责与修复痛点

| 层 | 职责 | 本轮解决的问题 |
|---|---|---|
| 剧情、人工选择和视觉规格 | 决定画面内容及事实优先级 | 不由提示词层随意改变人数、身份、服装或已确认规格；保留既有 P0 门禁 |
| 有效事实解析 | 汇合每人的资产、当前状态、动作和交互 | 本人事实独立解析；当前发型状态参与身份；鞋履按景别进入文本，资产绑定仍保留 |
| 公共块 | 表达全画面共同条件 | 修复镜头裁切反复追加、场景泛化和共同事件中硬编码人物朝向 |
| 人物块 | 表达该区域人物的可见事实 | 移除内部人物 ID、协议描述和无意义质量套话；删除 42 短语静默截断，保留尾部必要事实 |
| 负向范围 | 表达应排除内容 | 已知 no/not 指令按语义分流；接近未接触改写为可见间隙，不能改成握住；个人排除项不能全图广播 |
| Canonical 与编辑校验 | 合并可用补充，检查明确冲突 | 编辑不能替换掉完整人物基础块；明确人数、发色、眼色、发长、服装类别、看镜头冲突返回错误；不理解的否定句明确报错 |
| recipe 快照 | 固定此次任务事实及实际应用文本 | 保存版本、事实指纹、执行指纹和字段来源，worker 校验一致性；草稿确认继续复用任务快照 |
| Regional / Pose / ControlNet | 用区域、坐标和控制参数落实事实 | 不把几何 JSON 写进视觉文本；保留控制、遮罩和投影；Pose 覆盖同步有效动作事实和关系 |
| worker 局部 pass | 只修当前区域和任务 | 新版本统一编译，旧字符串只服务已保存历史配方；不再复制整图负向或整个场景到每次局部请求 |
| 门禁、审批、候选 | 判断程序执行可交付状态 | 编译失败不能降级成成功成品；传输失败依原门禁处理；仍是一轮草稿整体确认，成品自动入候选 |
| UI 和审计 | 展示公共/人物组织、来源和实际请求 | 任务详情可查看编译来源和基础/局部实际正负提示词；不增加逐项人工审批 |

## 阶段投影

| 阶段 | 使用的事实 | 范围保护 |
|---|---|---|
| 基础 | 公共块及每个人物块 | 保留原有基础生成分阶段政策、Regional、控制和构图后处理 |
| 身份 | 身份、表情、视线、遮挡 | 不引入身体比例或整套服装要求；本人眼镜等排除项保留 |
| 服装 | 当前衣物区域、状态 | 显式衣物细节替代全套衣物指令，避免上衣 pass 要求画出鞋或裙 |
| 道具 | 当前关系的对象、动作、手与表情 | 不借其他人物/关系；按接近、接触、释放阶段选择具体内容 |
| 手部 | 当前手及关系接触状态 | 不复制全身动作，保留腕部连续和当前接触/间隙 |
| 视线 | 身份、表情、实际目标方向和遮挡 | 实际视线细节替代基础视线，防止方向互相竞争 |
| 交接 | 当前交接关系及双方手与对象关系 | 保留交接专用控制，但使用实际双方位置和阶段，不固定左右角色 |

局部阶段都继承公共光照与风格，payload 的 mask、ControlNet 等其他字段保持原样。请求记录保存阶段、人物、关系、实际正负文本、指纹、发送状态和控制摘要。发送成功只代表传输成功，不代表语义或视觉验收。

例如接近包裹时使用 `right hand approaching the parcel with a visible gap`；人物不看镜头时正向写具体目标，如 `eyes focused on the parcel`，该人物负向保存 `looking at viewer, eye contact with camera`。不把“不接触”机械删掉后变成“握住包裹”。

## 兼容与失败

- 新任务使用 comic-facts-1。无版本及已存在的 sd15-visual-spec-v1 / sd15-staged-identity-v2 历史配方按旧路径执行，不重写用户已确认的任务。
- 新版本缺快照、指纹不一致、recipe 文本与快照不一致、未知版本或编译错误均明确失败。局部 pass 的编译错误即使被原可选修复 catch 捕获，也会在成品落盘/候选前重新硬阻断。
- 测试与构建使用内存数据库；workspace 是运行产物，排除出 TypeScript 项目源输入。未删除资产、数据库、候选或运行目录。

## 完整业务链复核与验证

1. 剧情/人工选择 → 视觉规格：保留现有优先级与确认门禁，地点自动编译继续提供本次请求内场景。
2. 视觉规格 → 提示词/交互契约：普通与 Regional 同源；单/多人、近/中/全景使用同一编译规则；动作阶段保留，不固定单一任务或人物 ID。
3. 契约 → recipe/payload：有效 Pose 后的动作/关系保存进快照；实际文本、负向、版本与指纹闭合。
4. Regional/ControlNet → 基础生成：保持 BREAK 人物块、mask、控制权重和原执行投影；不因文案精简删除控制。
5. 基础 → 身份/服装/道具/视线局部 pass：全部图像请求经过统一适配器，阶段仅选相关事实；检查本人负向、衣物区域、接触阶段、目标方向与光照继承。
6. 质量门 → 草稿整体确认 → 正式候选回写：保留像素/后处理/自动检测阻断、整体确认快照复用和事务式自动候选；编译冲突禁止进入最终候选。

复核发现的人物排除项丢失、人物负向广播、脸部继承身体/服装要求、目标视线重复以及可选 pass 吞掉编译失败均已在本 ISSUE 内处理。

验证：215/215 项项目测试、48/48 项 worker 与动作阶段逻辑测试通过；TypeScript、worker 语法检查和生产构建通过。覆盖三个景别、多人数、不同人物负向、五类动作机制与三个接触阶段、配方篡改/旧版本/缺快照，以及草稿确认复用。

**程序逻辑验收通过，未进行图片生成或视觉效果验收。** ISSUE-PROMPT-011 仅推进 fixed_pending_review，需诊断 Agent 独立复核。

## 保留的运行风险

提示词冲突识别是有界规则，不能理解所有自由英文表达；模糊否定会报错，任意新表述的全部语义矛盾不能保证自动发现。没有静默截断，但模型自身 token 上限仍可能影响长提示词。资产适配、模型随机性、真实视觉执行率和第三方插件效果仍是运行风险，本轮没有以测试结果宣称视觉效果已改善。

## 用户复现后的第二轮修复与结果

第一轮仅完成了组织框架，用户提供的输出证明事实解析和 worker 基础政策仍有缺口，不能以第一轮测试通过代表架构已达到全部目标。本轮重新打开 ISSUE-PROMPT-011，修复上游和执行消费。

确认根因：书籍类别泛化、expectedCount 固定为 1、取物 affordance 固定写“接近”而当前阶段是接触、把同步协议数组整体复制进视觉文本、旧自动视线默认为书页、衣物文本不按景别投影，以及 worker 延后道具政策再次追加一个物体和手部动作。手动阶段覆盖原先只改 Pose/局部关系，没有重编基础人物块。

新增统一职责：

- 交互契约保存具体对象、expectedCount、明确支持物、同一动作阶段。数量从本人动作解析，不能借背景或其他人物。未知量词仍按有界解析处理。
- 多段动作只对已识别“取出后接续触摸/查看”的末段建立当前可见阶段，保留推导假设；明确已确认或人工指定阶段优先。while 同时动作不作为取出完成依据。
- 人物字段把手部描述与每条交互关系分开；buildEffectivePromptPlan 供 API 与 UI 共用。Pose 改阶段/左右手后重编关系，不保留旧接近/接触文本。新 UI 可查看当前画面事实与姿态的编译预览。
- 胸上/腰上提示词不要求隐藏的裙、裤、鞋；全景保留整套服装。连衣裙使用可见上半部分，原衣物资产与绑定保持。画外衣物局部 mask 仍如实跳过。
- 数量进入 recipe、propInstancePlan、执行关系和控制轮廓；多件便携道具共享一组空间包络，保留对应数量的独立轮廓，不复制手或重复投影。1 件道具保留既有几何尺寸。
- 新配方的基础“道具细节延后”只简化表面细节，不重写数量、手部或视线，不跨 BREAK 追加到最后人物；原基础裁切辅助也不再给新配方追加姿态。历史配方保持原路径。

## 第三轮：同类场景根因与通用性（2026-10-05）

根因分为两层：上游把剧情压缩为泛化对象、固定数量和默认视线时丢失事实；下游各层独立拼提示词，再次猜测动作并覆盖已有事实。清理形容词只减少表象，不能恢复丢失的事实。

共享事实编译、人物范围负向和阶段选择解决第二层；具体对象、数量、阶段及可见服装投影解决第一层的已识别路径。本轮额外复现two paperback books和three transparent bottles数量误为1，修复共享数量规则，覆盖书、瓶、碗及不同修饰语，并测试介词和动作连接词阻断跨分句借数。221/221测试及类型检查通过。

可迁移到同类场景的是事实来源与优先级、同源编译、人物区域范围、阶段投影和实际请求审计，不是“两本书”的固定文本。现有程序矩阵覆盖不同人物数量、区域、景别、道具组与动作阶段；不意味着任意剧情都被正确解析。复杂多对象、多阶段、中文量词或含糊数量仍需上游结构化关系，数量缺失默认1仍是已知边界。组轮廓的并排布局是几何假设，并不证明像素正确。

全链复核见ISSUE-PROMPT-011第三轮记录。程序逻辑验收通过，未进行图片生成或视觉效果验收；模型随机性和实际视觉执行率保留为产品运行风险，状态fixed_pending_review。

## 第四轮：上游结构化事实与统一执行（2026-10-05）

已在现有ShotVisualSpec.interactions增加可版本化visualFacts，不建立第二份独立业务规格。旧schemaVersion 1.0保留，新增嵌套版本interaction-facts-1；旧规格缺失字段时保持缺失，标记legacy_text_inference_or_default。新AI道具规划必须完整提供；新字段形状进入缓存输入指纹，旧缓存不会被当作新规划结果。

最终数据链：剧情/人工选择 → 章节场景与连续性计划 → 当前分镜视觉规格 → 结构化事实归一化/校验及规格确认 → InteractionContract → 有效Pose投影 → PromptPlan → recipe/payload → Regional/ControlNet → 基础与各局部pass → 质量门/草稿整体确认 → 自动候选回写。

| 层级 | 唯一职责 |
| --- | --- |
| 剧情与人工选择 | 提供内容及明确选择，作为规划输入 |
| 章节视觉计划 | 提供场景和跨镜头连续性，不替当前镜头决定瞬时动作 |
| 当前视觉规格 | 保存具体对象、数量、动作阶段、接触、支持物及视线绑定 |
| 归一化与校验 | 保留字段、来源，拒绝非法数量、未知目标和共享实例矛盾 |
| 交互契约 | 将明确事实转换为现有实例、接触锚点、视线点与几何输入 |
| 有效Pose | 应用人工动作/阶段覆盖及坐标投影，同步有效状态 |
| 提示词编译 | 按人物、可见景别、基础/局部阶段表达事实，不重新猜数量 |
| 执行和候选 | 保留控制、mask及质量阻断，如实记录请求与状态 |

具体字段：object.label是具体英文物体名称，object.instanceId标识同一实例或组，object.count是1至16整数；actionId为受支持动作类型；phase为anticipation/contact/follow_through；contact包含hand、part和state；support包含label与state；gaze包含kind、targetId、surface与description；provenance按object/phase/contact/support/gaze保存source和evidence。
