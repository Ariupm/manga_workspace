## 3. 我的排查方法

沿完整链追同一个事实：剧情/人工选择 → 视觉规格 → 提示词与交互契约 → recipe/payload → Regional/ControlNet → 基础生成 → 身份/服装/道具/视线局部pass → 质量门/草稿确认 → 候选。

- 先判断需求是否具体、属于哪个人物，再看提示词是否表达一致，最后看实际请求是否真正携带控制。
- 特别查：坐标空间重复投影、人物/道具归属串位、近景与全身控制冲突、后序pass破坏前序结果、失败/未应用却记成成功。
- 每次局部修复都检查上下游和非目标场景；单/多人、左右区域、不同景别/动作/道具都要有证据，不能为一个job写特例。
- 优先纯函数、数据流和请求级测试；需要图像实验时固定模型/seed/输入，每次只改主要变量，保留失败结果。过去的SD实验是在用户明确授权下执行；工作区默认验收规则禁止解决/诊断 Agent 启动SD，接手者须按当前用户授权和角色规则执行，不能因为此文档自行重启服务。
- 记录改了什么、为何改、验证了什么、未验证什么。模型随机性和视觉执行率不能伪装成程序通过。
